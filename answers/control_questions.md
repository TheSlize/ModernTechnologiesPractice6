# Контрольные вопросы — Практика 6 (а вот они взяты с https://aliebraheem-fun.github.io/Modern-Programming-Technologies)

**1. GAV-координаты в Maven:**
groupId:artifactId:version — уникальный идентификатор артефакта. groupId — организация/пакет (com.example), artifactId — имя проекта/библиотеки, version — версия. Используются для однозначного определения зависимостей в репозитории Maven.

**2. compile vs test scope:**
`compile` — зависимость включается в classpath при компиляции, тестировании и запуске (попадает в итоговый JAR). `test` — доступна только при компиляции и запуске тестов, в финальный артефакт не включается (например, JUnit).

**3. Транзитивные зависимости:**
Зависимости зависимостей. Если подключить Hibernate, Maven автоматически подтянет его зависимости (jboss-logging, byte-buddy и т.д.). Проблема: конфликты версий — разные библиотеки могут требовать разные версии одной зависимости. Решается через `<dependencyManagement>`.

**4. Gradle vs Maven:**
Maven: XML-конфигурация, стандартизированный жизненный цикл, огромная экосистема плагинов, предсказуемость.
Gradle: Groovy/Kotlin DSL (короче и читаемее), инкрементальные сборки (быстрее), гибкая кастомизация, лучше для Android. Maven проще для новичков; Gradle быстрее на больших проектах.

**5. JDBC Driver:**
Реализация интерфейсов JDBC для конкретной СУБД. Каждая БД имеет свой протокол обмена данными — драйвер переводит вызовы JDBC API в команды, понятные конкретной СУБД. Поэтому для PostgreSQL нужен PostgreSQL-драйвер, для H2 — H2-драйвер.

**6. PreparedStatement vs Statement:**
`Statement` выполняет SQL-строку напрямую. `PreparedStatement` предварительно компилирует запрос с параметрами-заглушками `?`. Параметры передаются отдельно через setString/setInt, что защищает от инъекций и ускоряет повторные вызовы.

**7. SQL Injection:**
Атака, при которой пользовательский ввод интерпретируется как часть SQL-запроса. Пример: ввод `' OR '1'='1` в поле логина обходит авторизацию. PreparedStatement защищает, потому что параметры никогда не вставляются напрямую в текст запроса — они передаются отдельно и экранируются драйвером.

**8. Транзакция и ACID:**
Транзакция — группа операций, выполняемых как единое целое. ACID:
- Atomicity (атомарность) — либо все операции выполнены, либо ни одна.
- Consistency (согласованность) — БД переходит из одного корректного состояния в другое.
- Isolation (изолированность) — параллельные транзакции не видят незавершённых изменений друг друга.
- Durability (долговечность) — зафиксированные изменения сохраняются даже при сбое.

**9. ORM:**
Object-Relational Mapping — автоматическое отображение Java-объектов на таблицы БД. Преимущества: не нужно писать SQL вручную, переносимость между СУБД, работа с объектами вместо ResultSet. Недостатки: сложность настройки, N+1 проблемы, труднее оптимизировать запросы, «магия» скрывает реальные запросы.

**10. @Entity и @Table:**
`@Entity` сообщает Hibernate, что класс является сущностью и должен управляться ORM. `@Table` задаёт имя таблицы. Без `@Entity` Hibernate проигнорирует класс и выбросит исключение. Без `@Table` таблица получит имя класса (Movie → MOVIE).

**11. HQL vs SQL vs Criteria API:**
HQL оперирует именами классов и полей Java (Movie, title), а не таблицами (movies, title). Это обеспечивает независимость от схемы БД. Criteria API — это программный (типобезопасный) способ построения запросов через Java-код, без строк. HQL удобен для статичных запросов; Criteria API — для динамически собираемых запросов.

**12. hbm2ddl.auto = create:**
При каждом запуске приложения Hibernate удаляет существующую схему и создаёт новую. Все данные теряются. Подходит только для разработки и тестирования. В продакшене используется `validate` (проверить соответствие) или `none`.
